# Soul Dungeon: Reforged — 전투 씬 통합 지도

> 목적: 원작 `soul-dungeon`의 검증된 전투 **로직(두뇌)** 을 그대로 재사용하면서,
> presentation의 전투 화면만 **Flame 게임 씬(눈)** 으로 교체하기 위한 통합 지점 문서.
> 원작은 건드리지 않고 포크(`soul-dungeon-reforged`)에서 작업하는 것을 전제로 한다.

---

## 0. 한 줄 요약

**두뇌는 이미 준비됐고, 눈만 없다.**
전투 로직(`domain/combat`, 2.8만 줄)은 UI와 완전히 분리돼 재사용 가능하다.
문제는 현재 전투 UI가 **독립 위젯이 아니라 `GameScreen`에 인라인으로 얽혀** 있고,
전투가 **텍스트 로그 기반**이라 스프라이트 애니메이션·데미지 숫자가 아예 없다는 점이다.
단, 애니메이션에 필요한 데이터는 이미 `CardPlayResult`/`EnemyActionResult`로 흐르고 있고,
지금은 그것을 **텍스트로만 변환**하고 있을 뿐이다. → Flame 씬은 같은 데이터를 시각 이펙트로 변환하면 된다.

## 1. 재사용 자산 (손대지 않음)

| 계층 | 위치 | 규모 | 상태 |
|------|------|------|------|
| core (인프라) | `lib/core/` | — | 그대로 |
| **domain/combat (전투 두뇌)** | `lib/domain/combat/` | ~18.8k 줄 | **그대로** |
| domain 전체 | `lib/domain/` | ~28.4k 줄 | 그대로 (flutter_bloc/foundation/services만 의존, material 결합 0) |
| audio | `lib/audio/` | — | 그대로 (SFX 트리거만 재배선) |

`CombatBloc`은 **생성자 주입 + GameEventBus 통신**으로 이미 순수하게 분리돼 있다.
Flame 씬에서도 동일 인스턴스를 그대로 구동하면 된다.

### CombatBloc 생성자 의존성 (16종, `combat_bloc.dart:94`)
`gameEventBus`, `combatConfig`, `economyConfig`, `tierEffectCalculator`, `fleeConfig`,
`chainBonusConfig`, `floorsConfig`, `resolveCurseIds`, `resolveCardRelicIds`,
`resolveBlessingIds`, `resolveCardBlessingIds`, `resolveRelicIds`, `windAmuletRelicId`,
`unlockedCardIds`, `eliteRewardMultiplier`, `momentumConfig`
→ Reforged에서도 이 주입 계약을 그대로 유지한다.

## 2. 전투 상태 모델 = Flame 씬의 렌더 소스

전투의 살아있는 상태는 **`CardCombatActive`** (`combat_state.dart:389`). 카드 씬이 읽어야 할 필드:

| 필드 | 타입 | 씬에서의 용도 |
|------|------|--------------|
| `enemies` | `List<EnemyBattleState>` | 적 스프라이트 N개 (멀티몹 1~3) |
| `selectedTargetIndex` | `int` | 타겟 하이라이트/조준선 |
| `playerHp` / `playerMaxHp` | `int` | 플레이어 HP 바 |
| `playerBlock` | `int` | 방패 쉬머 강도 |
| `deckState` | `DeckState` | 손패 카드 렌더 (`hand`, `drawPile`, `discardPile`) |
| `actionPoints` / `maxActionPoints` | `int` | AP 오브 개수 |
| `playerStatuses` | `List<StatusEffect>` | 플레이어 버프/디버프 오라 |
| `intentRevealed` / `intentRevealTurns` | | 적 머리 위 의도 아이콘 표시 여부 |
| `bossData` / `currentBossPhase` | | 보스 페이즈 연출 |
| **`lastPlayResult`** | `CardPlayResult?` | **"방금 카드로 무슨 일이" → 공격/힐/방어 애니메이션 트리거** |
| **`lastEnemyActions`** | `List<(String, EnemyActionResult)>` | **"적이 무슨 행동을" → 적 공격/피격 애니메이션 트리거** |

### 애니메이션 트리거 데이터 (이미 계산되어 흐름)

`CardPlayResult` (`card_effect_resolver.dart:1337`) — 카드 1장 플레이 결과:
`damageResult`(피해량/치명/관통), `blockGained`, `healAmount`, `selfDamage`,
`newPlayerStatuses`, `newEnemyStatuses`, `drawCount`, `apGain` …
→ 각 필드가 0이 아니면 대응 VFX를 재생: 피해=슬래시+데미지팝+피격플래시, 방어=방패, 힐=회복파티클, 상태=배지 부착.

`EnemyActionResult` (`enemy_ai.dart`) — 적 1행동 결과:
`type`(공격/방어/버프/힐), `damage`, `block`, `healAmount`, `buffStrength`, `isEnrage`
→ 적 런지 애니메이션 + 플레이어 피격 + 넉백.

> **핵심:** 이 데이터는 지금도 매 턴 생성된다. 현재는 `CombatFlowManager.describeCardPlayResult()` /
> `describeEnemyAction()` 가 이걸 **텍스트 문장**으로 바꿔 로그에 쌓는다
> (`card_combat_handler.dart:353`, `:451`). Reforged는 같은 자리에서 **텍스트 대신(또는 병행) 시각 이펙트**를 쏜다.

## 3. 현재 presentation의 얽힘 지점 (교체 대상)

전투는 **전용 `CombatScreen`이 없다.** `GameScreen.build()`(`game_screen.dart:1736`) 안의
하나의 `Stack > SafeArea > Column`에 `if (_inCardCombat)` 조건부 섹션으로 인라인 조립돼 있다.

### 현재 전투 위젯 트리
```
GameScreen.build (game_screen.dart:1736)
└─ Stack
   ├─ AnimatedContainer(배경)              :1742
   ├─ SafeArea > GestureDetector > Column
   │  ├─ if(_inCardCombat) BlocBuilder<CombatBloc>  :1761  ← 적 영역
   │  │    └─ RetroWindowFrame > MultiEnemyAreaWidget :1808
   │  ├─ if(_inCardCombat) Expanded > '전투 기록' 텍스트 로그 :1869  (탐색과 공유)
   │  ├─ if(_inCardCombat) BlocBuilder<CombatBloc>  :1898  ← 플레이어 영역
   │  │    └─ MomentumGaugeWidget + PlayerHandAreaWidget(HP/AP만) :1956
   │  └─ if(_inCardCombat) '카드' 영역               :1977
   │       └─ ChoiceListWidget (카드=범용 선택지로 렌더) :1987
   ├─ CombatEffectOverlay (GameEventBus 구독, 전체화면 틴트) :2010
   └─ VignetteOverlay                       :2012
```

### 얽힘 목록 (Flame 교체 시 손대야 할 곳)
1. `game_screen.dart:1761`, `:1898` — 적/플레이어 영역 두 `BlocBuilder<CombatBloc>` 인라인 블록
2. `:1869` — 전투 로그 `_buildTextScrollArea` (탐색 모드와 **공유**됨)
3. `:1977` — 카드 영역이 범용 `ChoiceListWidget`/`_currentChoices`(`:1458`)를 **공유**
4. `_inCardCombat` 플래그가 build 전반(상태바/스크롤/하단바/미니맵)에 분산 (`:1760, 1869, 1895, 1977`)
5. 카드 탭이 범용 `choice_router`(`play_card_` prefix)를 경유 → Flame 내부 입력으로 대체 필요

### 스프라이트 렌더링 현황
- 정적 `Image.asset` (idle/attack/hurt 구분 **없음**). `filterQuality: none`으로 픽셀 샤프 유지.
- 경로 매핑: `pixel_art_assets.dart` — `enemySprite(id)`(:103), `bossSprite(id)`(:109)
- 유일한 움직임: `animated_boss_sprite.dart` — 보스만 2초 호흡(부유+스케일)
- **플레이어 스프라이트는 전투에 아예 없음** (HP/AP 아이콘만)

### 카드 탭 → PlayCard 흐름 (현재)
```
손패 → CombatFlowManager.buildCardHandChoices (combat_flow_manager.dart:344)
     → ChoiceData(id:'play_card_{cardId}_{i}')
     → ChoiceListWidget 탭 (choice_list_widget.dart:219)
     → _onChoiceSelected (game_screen.dart:1049)
     → ChoiceRouter (choice_router.dart:86, 'play_card_' 분기)
     → handlePlayCard → CardCombatHandler.handlePlayCard
     → combatBloc.add(PlayCard(...))  (card_combat_handler.dart:306)
     → combatBloc.stream.first 로 결과 await → 텍스트 블록 추가
```

## 4. 교체 전략 — 2단계

### 1단계: 리팩터 (원작에도 적용 가능, 리스크 낮음)
`game_screen.dart:1760~2004`의 `if (_inCardCombat)` 블록 전체를
**하나의 독립 위젯 `CardCombatView`** 로 추출한다.
- 입력: `CombatBloc` 인스턴스 + `MomentumBloc` + 콜백(카드탭/턴종료/도주/타겟선택)
- 이 단계만으로 전투가 "격리된 위젯"이 되어 이후 교체가 안전해진다.
- 텍스트 로그·범용 선택지 공유(2·3번 얽힘)를 이때 전투 전용으로 분리한다.

### 2단계: 씬 교체 (Reforged 전용)
`CardCombatView` 내부를 `GameWidget`(Flame)으로 교체한다.

```
CardCombatView (Flutter 위젯)
├─ GameWidget<CombatFlameGame>          ← 전투 씬 (스프라이트/VFX/파티클)
│    - 상태 소스: CombatBloc.stream 구독 → CardCombatActive 반영
│    - 트리거: lastPlayResult/lastEnemyActions diff → 애니메이션 큐
│    - 컴포넌트: PlayerActor, EnemyActor[], DamageNumber, SlashVFX,
│                ShieldShimmer, StatusAura, IntentIcon, ScreenShake
└─ Flutter 오버레이 (Flame overlay 또는 Stack 상단)
     ├─ 손패 카드 UI (실제 카드 위젯 — 범용 선택지 대체)
     ├─ 기세 게이지 (MomentumGaugeWidget 재사용 가능)
     └─ 턴 종료/도주 버튼
```

- **UI/메뉴/상점/이벤트는 Flutter 위젯 그대로** 둔다. Flame은 전투 씬에만.
- **SFX**: 지금은 GameEventBus 구독으로 재생 → 그대로 유지하되,
  Flame 애니메이션 타이밍과 동기화(공격 임팩트 프레임에 `combat_hit` 재생).
- **"서술자 왜곡"은 유지·강화**: 왜곡 발동 시 씬 채도 down + 스프라이트 잔상 + 텍스트 글리치.
  domain 값은 절대 변경 금지(원작 규칙) — presentation 표시만 왜곡.

### 상태 → 씬 동기화 패턴
```
CombatBloc.stream (CardCombatActive)
  → CombatSceneController (신규, presentation)
      - prev vs next 상태 diff
      - lastPlayResult 존재 → 플레이어 공격/힐/방어 애니 enqueue
      - lastEnemyActions 존재 → 각 적 행동 애니 enqueue
      - enemies[i].currentHp 감소 → 데미지 숫자 + 피격
      - enemies[i].isDead 전환 → death 디졸브
      - playerHp 감소 → 플레이어 피격 + 화면 흔들림
  → 애니메이션 큐를 순차 재생 (겹침 방지, 카드플레이 300ms 윈도우 참고)
  → 재생 완료 후 다음 입력 허용
```
현재 `card_combat_handler.dart`가 `stream.first`로 결과를 명령형 await하는 구조라,
이 지점을 "텍스트 쌓기" 대신 "씬 애니 큐 재생 완료 await"로 바꾸면 흐름이 자연스럽게 이어진다.

## 5. 스프라이트 애니메이션 자산 (신규 필요)

기존 픽셀아트 75종은 **단일 정적 프레임**. 씬을 살리려면 상태별 프레임 추가:

| 액터 | 필요 상태 | 최소 프레임 |
|------|-----------|-------------|
| 플레이어(직업 9종) | idle / attack / hurt / (death) | idle 2 + attack 2~3 + hurt 1 |
| 일반/엘리트 적 40종 | idle / attack / hurt / death(디졸브) | idle 2 + attack 2 + hurt 1 |
| 보스 15종 | idle / attack / phase전환 / death | 보스별 3~4 상태 |

> 우선순위: **1층 적 7종 + 직업 1종(전사)** 만 먼저 만들어 파일럿 검증.
> 프레임 생성은 기존 `tools/gen_*.py` 픽셀 파이프라인 확장으로 대응 가능.

## 6. 파일럿 범위 (1단계 프로토타입)

"연출형 전투가 재밌어 보이나"를 눈으로 확인하기 위한 최소 수직 슬라이스:

- [ ] `CardCombatView` 위젯 추출 (리팩터)
- [ ] 전사 vs 1층 적 1종, 단일 전투
- [ ] Flame 씬: 플레이어/적 스프라이트 4상태 + 카드 슬래시 VFX + 데미지 숫자 + 화면 흔들림
- [ ] 실제 손패 카드 위젯 (범용 선택지 대체) + 탭→PlayCard
- [ ] `lastPlayResult`/`lastEnemyActions` → 애니 큐 동기화
- [ ] SFX 타이밍 동기화 (임팩트 프레임)

이 슬라이스가 되면 나머지(멀티몹·보스·상태효과·왜곡연출)는 같은 패턴의 확장이다.
